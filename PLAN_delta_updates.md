# Дельта-обновления: почему сейчас катается всё и как это чинить

Статус: дизайн, не реализовано. Все числа — замеры на боевом Keenetic (aarch64,
500 МБ, Entware на USB), не оценки.

## 1. Что происходит сегодня

Три механизма обновления, дельта только в одном:

| путь | что делает |
|---|---|
| `z2k update` (`z2k.sh:1197`) | самообновление одного файла; до него — полный bootstrap |
| `au_apply_patch` (`auto_update.sh:579`) | **настоящая дельта**: staging → sha-less проверка → атомарный rename |
| `au_apply_reinstall` (`auto_update.sh:752`) | `sh z2k.sh install` — всё заново |

Замерено из `/opt/var/log/z2k-auto-update.log` боевого роутера — три подряд
reinstall'а: **123 с / 111 с / 116 с**, плюс фиксированный `sleep 60`
health-check ≈ **3 минуты на обновление**.

Что делает один reinstall независимо от размера изменения:

- **92 отдельных HTTPS-фетча**, каждый через ладдер raw→jsdelivr→gh-proxy→DoH,
  без переиспользования соединения и без `--compressed`.
  Замер: 0.37 с/файл поштучно → **34 с**; те же файлы одним curl с keepalive —
  0.09 с/файл → **8 с**.
- `opkg update` по обоим фидам + 12 проверок «уже установлен».
- Тарбол движка на **10 архитектур, из которых 9 удаляются сразу после
  распаковки** (`z2k_slim_release_binaries`, `install.sh:1050`).
- RKN-список на 125 451 домен и geosite-дедуп по 79 504 строкам.
- HWNAT/offload, TCP-тюнинг, netfilter-хук.
- Рестарт сервиса.

ETag-кэш (`_z2k_curl_etag`) на этом пути **мёртв структурно**: `z2k.sh:1413`
делает `rm -rf "$WORK_DIR"` до фетчей, а `deploy_critical_file:60` удаляет
`.etag` сразу после (NDM пытается исполнить `.etag` как скрипт → exit 127).
`If-None-Match` не уходит никогда.

## 2. Почему «просто помечать релизы как patch» — неверный ответ

Это была первая гипотеза, и она не выдержала проверки. `changed_files` в
UPDATES.json — сырой `git diff --name-only` (`release.sh:79`), он **не описывает
payload**:

- `lib/config.sh` и `lib/install.sh` — **install-time генераторы, а не runtime**.
  Скопировать `lib/config.sh` в `/opt/zapret2/lib/` = записать файл, который
  никто не прочитает до следующей установки.
- `r-64` выглядит как «одна правка `lib/config.sh`», а на деле апгрейд движка
  через **движущийся** указатель `releases/latest` (`install.sh:1287`) —
  разрешить его можно только запустив инсталлер.

Настоящих «пересобрали демон, а поехал полный reinstall» — **r-64.5, 2 из 115**.
Популяция «только `lib/*`» — 11 из 69, и ни один не может быть патчем.

Опаснее: автовывод типа из `au_install_paths` **сломал бы установку**. У `lib/*`
маппинг уже есть (`:414-420`), поэтому правило «все пути мапятся → patch» тихо
понизит ~45 install.sh-релизов до патчей. А `au_apply_patch` **никогда не
запускает install.sh**, значит новые opkg-зависимости, ipset'ы, NDM-хуки и ключи
конфига не появятся, пока `installed_tag` уезжает вперёд. Это ровно класс бага
r-59.9, замемориализованный в комментариях `auto_update.sh:375-403`.

## 3. Корень: склеены две независимые вещи

Один флаг `patch|reinstall` управляет сразу двумя ортогональными вопросами:

1. **какие байты скачать**
2. **какие install-шаги выполнить**

Отсюда и симптом: чтобы выполнить один install-шаг, приходится скачать всё.

**Дизайн-ход: расцепить их.** Байты выводятся из содержимого (хеши), шаги
объявляются релизом явно.

## 4. Манифест

CI генерирует `MANIFEST.json` на релиз — единственный источник правды по
артефактам:

```json
{
  "schema": 1,
  "tag": "r-67",
  "engine": {
    "version": "v1.0.3-z2k-r0",
    "tarball": { "linux-arm64": {"sha256": "...", "size": 4404... } }
  },
  "files": [
    { "path": "files/S99zapret2.new", "sha256": "...", "size": 61234,
      "target": "/opt/etc/init.d/S99zapret2", "mode": "755" },
    { "path": "lib/menu.sh", "sha256": "...", "size": 90002,
      "target": "/opt/zapret2/lib/menu.sh", "mode": "644" }
  ],
  "steps": ["config_regen", "restart:S99zapret2"]
}
```

Свойства, которые решают задачу:

- **`target` генерируется, а не поддерживается руками** → класс дрейфа
  `au_install_paths` исчезает структурно. Сегодня набор артефактов перечислен в
  пяти местах, которые расходятся; станет — в одном.
- **`engine.tarball` с хешем** → апдейтер сравнивает с установленным и
  **пропускает 4.4 МБ**, когда движок не менялся. Это крупнейшая единичная
  экономия. Заодно исчезает движущийся `releases/latest`: версия пиньится.
  Тарбол — **на свою арку**, а не 10 с удалением 9.
- `sha256` каждого файла даёт **проверку целостности до установки**, которой у
  патч-пути сейчас нет: `au_apply_patch` делает cp→chmod→mv без валидации, тогда
  как install.sh гоняет бинари через size>500000 + ELF-magic + `--help`.
  Манифест уравнивает это для всех файлов.

Размер манифеста — порядка 30 КБ (замер: индекс sha256 по 270 файлам = 29 541
байт), со сжатием ~8 КБ. Один фетч.

## 5. Алгоритм обновления

```
1. fetch MANIFEST.json               (1 запрос, --compressed)
2. если engine.version != установленной → шаг `engine`, иначе тарбол не трогаем
3. посчитать sha256 установленных target'ов     (замер: 0.23 с на 270 файлов)
4. changed = target отсутствует ИЛИ sha256 разошёлся
5. fetch только changed — ОДНИМ curl с keepalive + --compressed
6. проверить sha256 каждого скачанного ДО установки; расхождение → abort целиком
7. установить атомарно (tmp в том же каталоге + rename) — как уже делает
   au_apply_patch:640-676
8. выполнить только объявленные `steps`
9. записать /opt/zapret2/.z2k-manifest (индекс для быстрого пути)
```

Шаг 3 не требует доверия к сохранённому индексу: он считает по факту с диска,
поэтому переживает ребут, `rm -rf WORK_DIR`, оборванную установку и ручные
правки. Индекс `.z2k-manifest` — только ускорение, не источник правды.

## 6. `steps` — замена флагу patch|reinstall

Словарь (выполняется в этом порядке, только объявленное):

| шаг | когда нужен |
|---|---|
| `deps` | добавились/сменились opkg-зависимости |
| `engine` | сменилась версия движка (иначе тарбол не качается вообще) |
| `lists` | нужен принудительный рефетч списков доменов |
| `config_regen` | изменился генератор `NFQWS2_OPT` (`lib/config*.sh`) |
| `fw_hook` | изменился NDM netfilter-хук |
| `tuning` | HWNAT/offload, TCP-тюнинг |
| `restart:<svc>` | какие сервисы бросить |

`release.sh` **выводит набор по умолчанию** из изменённых путей, автор может
переопределить. Вывод обязан быть **консервативным**: неизвестный путь → полный
набор. Режим отказа должен быть «сделали лишнее», а не «молча пропустили» —
именно в эту сторону ломался r-59.9.

Это прямо закрывает возражение безопасности из п.2: релиз, трогающий
`lib/install.sh`, объявляет `deps` (или что он там добавил) и **выполняет
только этот шаг, не скачивая 26 МБ**.

## 7. Что это даёт

Типовой релиз (несколько shell-файлов):

| | сейчас | станет |
|---|---|---|
| запросов | ~92 | 1 манифест + 1 батч |
| байт | ~26 МБ | десятки КБ |
| `opkg update` | всегда | только по шагу `deps` |
| тарбол движка | всегда, 10 арок | только если сменилась версия, своя арка |
| рестарт | 25 с | 1.7 с (уже сделано) |
| health-check | `sleep 60` | опрос живости |
| **итого** | **~180 с** | **единицы секунд** |

Релиз с апгрейдом движка по-прежнему тянет тарбол — но один, свой, и только
когда хеш реально изменился.

## 8. Миграция

Без flag day. Манифестный путь добавляется **рядом** с существующим:

- манифест отсутствует/битый/`schema` неизвестна → фоллбэк на сегодняшнее
  поведение (`au_decide` → patch/reinstall);
- `.z2k-manifest` бутстрапится при первой манифест-совместимой установке;
- `UPDATES.json` остаётся append-only (историю не трогаем —
  matching by-order), `steps` добавляется опциональным полем к записям.

## 9. Техдолг, который это удаляет

- `au_install_paths` — 129 строк руками поддерживаемого `case` → генерируемый
  `target`;
- пять расходящихся перечислений артефактов → один генератор;
- мёртвая ETag-машинерия → хеш-сравнение её замещает;
- бинарный `patch|reinstall` → `steps`;
- отсутствие проверки целостности на патч-пути → единый sha256-гейт.

## 10. Что нужно померить до реализации

- сколько из оставшихся ~76 с занимают `opkg update`, тарбол, RKN и geosite
  по отдельности (сейчас не разложено — обещать по ним нельзя);
- поведение батч-фетча на мобильных провайдерах, где ладдер реально
  проваливается на слои 2-5: батч из одного curl теряет пофайловый фоллбэк,
  нужен ретрай пооставшимся файлам, а не всему батчу.

## 11. Чего в дизайне сознательно нет

- Не переезжаем на .ipk/opkg-фид. Это структурно чище (так живёт
  nfqws2-keenetic), но ломает и способ доставки, и способ отката, и
  пользовательские оверрайды — отдельный разговор.
- Не трогаем частоту релизов. Рычаг реальный (у z4r «быстрые обновления»
  ровно потому, что автообновления нет вообще), но это политика, не код.
