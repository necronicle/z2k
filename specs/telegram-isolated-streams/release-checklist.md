# Проверка парка перед релизом

Этот список — ворота выпуска, не утверждение «весь парк уже проверен».

1. Непосредственно перед обновлением снять приватный baseline:
   `ssh root@VPS python3 - < vps/observability/fleet-snapshot.py > baseline.json`.
   Ключ/хост взять из RUNBOOK. Скрипт только читает; секреты не печатает.
   Зафиксировать PID, live installations, отпечатки установок, streams, sessions,
   RSS, доступную память, CPU, сеть, TLS/авторизационные ошибки и дисковые журналы.
2. Сверить живую конфигурацию с `vps/bin/verify.sh`. Сейчас nginx.conf отличается
   от репозитория; не затирать это расхождение при применении своей правки.
   Сохранить бинарник, конфиги, ключи и реестр для отката. Увеличить общий предел
   основного VPS до10000, подготовить релей с совместимым объявлением квоты.
   У маленьких назначенных/пользовательских серверов проверить персональную квоту:
   quota1 физически допускает только один изолированный поток одновременно.
3. Проверить новый вход из пользовательской сети: TLS, прежний ключ, реальные
   сообщения/медиа, регистрацию и независимую доставку подписанного обновления.
   Owner разрешил экспериментальные реконнекты; это не отменяет сохранение отката.
4. Проверить матрицу доставки:9 архитектур и алиасы из build-matrix.tsv, секрет,
   версию в бинарниках, подписи манифеста, install_map и публичные кэши. Версия
   итогового релиза потребует обычной пересборки — текущие файлы имеют p-87.25.
5. Контрольные реальные установки: ARM64 (полевой тест выполнен), ARMv7, MIPS
   soft-float; несколько устройств за одним роутером. Отдельно старый v1/v2 клиент,
   d2k-клиент на общем VPS, назначенный и пользовательский сервер, DNS/IPv6,
   переподключение после потери связи. Go race/cross-build не заменяют эти проверки.
   Изменение Go-клиента z2k само по себе не обновляет отдельный C-клиент d2k.
6. Сравнить после контрольного обновления: установки/отпечатки и полезные потоки
   не должны исчезнуть; число сессий закономерно вырастет и больше не равно числу
   установок. Проверять дельты счётчиков только при одинаковом PID, иначе reset.
   Проверить также скорость роста журналов и ночной recycle при RSS900MiB:
   новый нормальный профиль памяти не должен ошибочно трактоваться как утечка.
7. Расширять выпуск после контрольной проверки, наблюдать полный цикл обновления.
   При деградации остановить распространение, восстановить прежние файлы/конфиги
   по согласованному плану. Возврат файлов не восстанавливает уже закрытые TCP.

Из административного API нельзя достоверно получить полную архитектурную/версионную
перепись живого парка. Для этого нужны контрольные устройства и данные доставки;
один общий HTTP200 или нагрузочный тест не является проверкой всего парка.
