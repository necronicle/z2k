# Штатная замена Telegram-транспорта

После обновления клиента каждый TCP-поток автоматически получает отдельное
соединение к VPS. Включать режим не нужно. Потоки разных устройств не возвращаются
в один общий канал. Содержимое Telegram не расшифровывается, тип «медиа/сообщения»
не угадывается. Звонки эта правка не исправляет.

Локальный потолок —64 сессии на установку. Релей сообщает свою квоту после
авторизации; клиент оставляет одну сессию резерва (квота1 остаётся1). Для старого
релея без объявления квоты применяется48. На основном сервере с квотой64 это
даёт63 рабочих слота с новым релеем,48 — со старым. Это не16 на весь дом.
Один IP устройства занимает не больше16 слотов; ожидающие устройства обслуживаются
по кругу. IP — технический ключ, не идентификатор человека; NAT перед прокси может
объединить устройства. Пять устройств не получают обещания80 одновременных слотов:
при исчерпании общей или индивидуальной квоты лишнее TCP сразу закрывается, как
в успешном эксперименте. Держать принятое соединение45с без полезных данных оказалось
плохим решением: полевой тест дал ухудшение. До четырёх рукопожатий потоков данных идут одновременно, как в первом эксперименте, без
добавленной паузы между запусками. Ожидание свободного места для рукопожатия
ограничено10с; живые потоки не вытесняются. Ошибка одного транспорта не ставит
соседей на общую паузу. Краткая проверка маршрута может занять дополнительное
рукопожатие, но учитывается в общем бюджете сессий.

`TG_RELAY_SESSIONS=1..64` в `/opt/zapret2/config` может уменьшить локальный потолок;
это настройка ёмкости, не переключатель старого/нового режима. Настройка применяется
при очередном штатном запуске. Ошибочное значение оставляет встроенный потолок.
Старые бинарники пропускают неизвестный параметр. `TG_ISOLATED_STREAMS` из первого,
неопубликованного коммита больше не используется.

Серверы с маленькой персональной квотой должны получить достаточную квоту перед
переходом на отдельные потоки. Пользовательские/назначенные URL не подменяются.
На основном VPS до изменения:6000 общих сессий, около7300 активных потоков. Поэтому
обновлять весь флот раньше подготовки серверной ёмкости нельзя. В коммите готовится
конфигурация10000 сессий; это не отключение ограничений памяти или очередей.

Для релиза: применить проверенные серверные изменения с сохранённым откатом,
клиентские `mtproxy-client/builds` уже пересобраны для9 архитектур с Go1.25.13
и штатным секретом, с текущей версией манифеста. При смене версии пересобрать
их стандартным release-процессом, затем включить итоговый коммит в обновление. Поднятие новых бинарников,
релиз и миграция всего флота — отдельные действия; коммит не делает их
автоматически. Следить за общей памятью, CPU, TLS-отказами, сетью и восстановлением
после обрыва. Локальные нагрузочные тесты не заменяют пользовательскую WAN-нагрузку.
