# vps — узел релея как управляемая система

Через этот узел проходит весь флот роутеров. До 31.08.2026 он существовал как
машина, которую правили руками: копия конфигурации в репозитории разошлась с
живой на 47 строк, и никто об этом не знал. Здесь он описан, сверяем и
раскатываем.

## С чего начать

| хочу | команда |
|---|---|
| понять, как узел устроен и почему так | [DESIGN.md](DESIGN.md) |
| узнать, совпадает ли живое с записанным | `sh vps/bin/verify.sh` |
| посмотреть, что происходит прямо сейчас | `sh vps/observability/collect.sh 120` |
| раскатать правку | `sh vps/bin/deploy.sh` затем `--apply` |
| действовать по ситуации | [RUNBOOK.md](RUNBOOK.md) |

## Что где лежит

```
DESIGN.md                модель узла: замеры, отказы, ёмкость, решения и их цена
RUNBOOK.md               что делать в конкретной ситуации
bin/verify.sh            сверка живого узла с репозиторием (ничего не меняет)
bin/deploy.sh            раскатка: проверка, reload без разрыва, сверка после
bin/net-tuning.sh        разнос приёма пакетов по ядрам (RPS)
config/                  конфигурация один в один с машиной, секреты замаскированы
observability/collect.sh сигналы узла за окно
```

## Три правила

1. **Сверка перед правкой.** Расхождение — это чужая работа, а не мусор.
2. **Reload, а не restart.** Перезапуск nginx рвёт ~1800 туннелей, релея —
   ~3500. Всё, что требует перезапуска, делается в окно и с предупреждением.
3. **Замер после.** Правка `listen` может молча не примениться на
   унаследованном сокете, а `sysctl` — быть перекрыт файлом, который
   применяется позже. Сделано — значит подтверждено фактом, а не тем, что
   команда не выдала ошибку.

## Секреты

В репозитории их нет: в конфигурации они заменены на `<СЕКРЕТ>`, и такие файлы
раскаткой не переносятся. Сверка накладывает ту же маску на обе стороны, поэтому
сравнивается структура запуска, а не значения ключей.
