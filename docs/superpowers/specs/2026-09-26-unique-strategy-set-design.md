# Уникальный набор стратегий — спецификация

## Цель

Добавить в «Стратегии → Автоподбор» экспериментальный сценарий, который последовательно измеряет стратегии для YouTube, Googlevideo и Instagram, затем формирует стратегию пула RKN TCP на основе нескольких контрольных доменов и сохраняет все четыре результата в соответствующие пользовательские пулы.

Сценарий должен завершаться одним согласованным применением либо не менять конфигурацию вовсе. На странице и в журнале видны этап, домен, результат, причина выбора RKN-строки и фактическое время выполнения.

## Интерфейс и запуск

- Вверху вкладки «Автоподбор» появляется кнопка «Создать уникальный набор» с пометкой «ЭКСПЕРИМЕНТАЛЬНО!!!» и оценкой длительности «в среднем около 20 минут».
- Подпись уточняет, что время зависит от сети и на сложных линиях может заметно вырасти.
- Сценарий запускается одним серверным фоновым заданием с последовательными этапами и журналом прогресса. Закрытие окна журнала не отменяет серверную работу.
- Если в одном из целевых пулов уже сохранена пользовательская стратегия, перед запуском панель сообщает, какие пулы будут заменены. Предупреждение также указывает, что собственная стратегия задаёт поведение всему пулу, а не только тестовому домену.
- Повторный запуск блокируется, пока такой же сценарий ещё работает.

## Последовательность замеров

Все измерения выполняются по очереди одним заданием:

1. `youtube.com`, режим «И те, и другие» (`mixed`) → пул `yt_tcp`.
2. `googlevideo.com`, режим «И те, и другие» (`mixed`) → пул `gv_tcp`.
3. `instagram.com`, режим `quic` → пул `quic`.
4. TCP-подбор «И те, и другие» (`mixed`) по доменам в приоритетном порядке: `discord.com`, `instagram.com`, `rutor.org`.

Этапы 1–3 используют текущий измеритель «Подбор по домену». Они не меняют конфигурацию во время замеров. Результаты сохраняются во временное рабочее состояние задания, поскольку существующий endpoint хранит только последний замер.

## Выбор стратегии RKN TCP

В текущем проекте `z2k-detect classify` возвращает один первый найденный приём для одного домена. Первая версия не запускает полный перебор всех теоретически возможных стратегий.

- Для каждого из трёх доменов этапа 4 измеритель ищет один приём, общий для TLS 1.3 и TLS 1.2.
- Результаты считаются пересечением, только если строки параметров совпадают после удаления краевых пробелов и свёртки повторных пробелов. Все значимые параметры строки сравниваются без изменений.
- Если непустая одинаковая строка найдена для всех трёх доменов, она выбирается для `rkn_tcp`, а в отчёте указывается проверенное покрытие `3/3`.
- Если общей строки среди первых найденных приёмов нет, используется измеренная строка `discord.com` как эталон. Панель сообщает, что полного пересечения не найдено и применён Discord-fallback. Это не утверждает, что исчерпывающий перебор не мог бы найти другую общую строку.
- Если для `discord.com` строка не найдена, весь сценарий завершается без сохранения пулов. Отсутствие стратегии для `instagram.com` или `rutor.org` означает отсутствие подтверждённого общего пересечения, после чего применяется Discord-fallback.
- Проверка подтверждает результат измерителя на соответствующих TCP/TLS-зондах, но не гарантирует полную работу всех функций сайтов, CDN, медиа и приложений.

## Проверка и применение набора

Целевые пулы: `yt_tcp`, `gv_tcp`, `quic`, `rkn_tcp`.

1. Для каждого результата панель строит полный профиль штатной функцией `strategy_complete_line`, используя каркас соответствующего пула.
2. Каждая строка проверяется в своём пуле штатным `strategy_validate`, затем все четыре строки проверяются вместе как один будущий конфиг. Только после успешной общей проверки подготавливаются резервные копии и временные файлы.
3. Если обязательный замер, сборка или проверка завершились ошибкой, текущие пользовательские стратегии остаются без изменений; журнал и экран результата сохраняют диагностику ошибки. Отсутствие общей строки для Instagram/Rutor — не ошибка: в этом случае действует описанный выше Discord-fallback.
4. После проверки новые файлы четырёх пулов устанавливаются как один набор, конфигурация регенерируется один раз, работающий сервис перезапускается один раз. При ошибке применения прежние файлы и конфигурация восстанавливаются.
5. Если сервис выключен, файлы и конфигурация сохраняются, но панель сообщает, что для фактического применения сервис нужно запустить.

Запись в пользовательские пулы заменяет их прежние стратегии и применяется ко всему соответствующему пулу. Набор не правит штатные файлы `Strategy.txt` и списки доменов.

## Ошибки и отображение результата

- Для каждого этапа журнал показывает запуск, домен, режим, длительность и найденную строку либо понятную причину, почему её нет.
- При техническом сбое или отсутствии применимой строки на любом из первых трёх этапов, а также при отсутствии строки Discord, сценарий останавливается до записи конфигурации.
- При недоступности `instagram.com` или `rutor.org` в финальном RKN-этапе сценарий показывает неполное пересечение и применяет строку Discord, если она успешно измерена.
- После успешного завершения отображаются все четыре применённые строки, их пулы, итог RKN (`3/3` или Discord-fallback), тестовые домены и полная длительность.
- Оценка «около 20 минут» является средним ориентиром, а не гарантированным максимальным временем.

## Документация и проверки

README обновляется вместе с функцией: назначение кнопки, последовательность доменов и режимов, оценка времени, влияние пользовательских стратегий на весь пул, правило общего RKN-приёма и поведение при fallback/ошибке.

Проверки должны покрыть:

- правильный порядок этапов, домены и режимы запуска;
- совпадающие строки и выбор `3/3`;
- несовпадающие строки и Discord-fallback;
- отсутствие Discord-стратегии и ошибку каждого из четырёх этапов без изменения файлов;
- валидацию всех четырёх пулов до сохранения, одну регенерацию и один перезапуск;
- откат старых файлов/конфига при ошибке применения;
- отображение предупреждения о замене, экспериментальной пометки, прогресса, оценки времени и итогового покрытия;
- регрессию текущего одиночного «Подбора по домену».

Перед релизом провести полный прогон на роутере и убедиться, что четыре новые строки вошли в активный конфиг после единственного перезапуска. Зафиксировать фактическое время; если средний ориентир заметно расходится, скорректировать подпись.

## Вне объёма первой версии

- Встраивание или запуск `blockcheck2`.
- Полный перебор всех возможных стратегий ради математически исчерпывающего пересечения.
- Автоматический перебор всего установленного RKN-списка.
- Изменение списков доменов, WARP, DNS или стратегий других пулов.
- Сохранение частичного набора при неудаче одного из обязательных этапов.
