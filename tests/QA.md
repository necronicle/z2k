# QA-процедура релиза z2k

Документ существует потому, что четыре подряд «починено» оказались непочиненными, и каждый
раз причина была одна и та же: **проверяли не то, чем пользуется человек.** Ниже — что
именно гоняется, что каждый слой ловит, и чего не ловит ни один.

## Слои проверки

| Слой | Команда | Что ловит | Чего НЕ ловит |
|---|---|---|---|
| Юнит-тесты (shell) | `sh tests/run_all.sh` | логику функций на заглушках | всё, что зависит от настоящего роутера |
| Юнит-тесты (Go) | `cd rt-proxy && go test -cover ./...` | поведение прокси на живых сокетах | реальный пул, реальный провайдер |
| Приёмочные спеки | `sh tests/bdd.sh` | пользовательские исходы целиком | то, чего нет в `.feature` |
| Мутационные | `sh tests/mutation.sh` | **бесполезные тесты** | поведение, для которого нет мутанта |
| Линтеры | `shellcheck`, `luacheck`, `go vet` | синтаксис, портируемость | смысл |
| POSIX-прогон | `dash tests/test_*.sh` | bash-измы, которые упадут на busybox | различия самого busybox |
| Живой роутер | см. ниже | всё остальное | другую архитектуру и другого провайдера |

Ключевой слой — **мутационный**. Зелёные тесты сами по себе не значат ничего: они могут
проверять заглушки. Мутационный прогон берёт настоящие регрессии, вносит их в код и требует,
чтобы сьют покраснел. Выживший мутант — это незащищённое поведение, независимо от процента
покрытия. Именно так были найдены три дыры, которые покрытие показывало зелёными.

## Обязательный прогон перед релизом

```sh
sh tests/run_all.sh                                   # юнит + приёмочные
for t in tests/test_*.sh; do dash "$t" || echo "POSIX FAIL: $t"; done
cd rt-proxy && CGO_ENABLED=0 go test -count=1 -cover ./... && cd ..
sh tests/mutation.sh                                  # 0 выживших обязательно
# Проще и надёжнее — прогнать весь локальный CI, он держит маску в одном месте:
sh scripts/ci_local.sh
luacheck files/lua/*.lua --codes -q
```

Плюс сборка: все бинарники обязаны **воспроизводиться побайтово** при повторной сборке
(`-trimpath -buildvcs=false`, пиннинг тулчейна). Расхождение означает, что репозиторий и то,
что ставится людям, — разные вещи.

## Проверка на живом роутере

Юнит-тесты не поймали ни одного из багов, которые реально жгли: аппаратный offload, коллизию
адресов NDM, узлы прокси, отдающие рукопожатие и виснущие на данных. Поэтому:

1. **Синхронизировать** роутер с рабочим деревом и **сверить хэши** каждого изменённого файла.
   Отчитываться «исправлено» до этого шага нельзя — правка в репозитории не видна пользователю.
2. **Холодный путь целиком**: спрятать бинарь и ключ устройства, прогнать установку с нуля.
   Унаследованное состояние маскирует именно те ветки, которые ломаются у новых пользователей.
3. **Пачкой, а не по одному.** Последовательные запросы обходят проблему, которая проявляется
   при старте браузера: 8 параллельных соединений размазываются по всему кольцу узлов.
4. **После простоя.** Часть отказов видна только на холодную — туннель отваливается по idle,
   узел успевает испортиться между проверками.
5. **Не трогая роутер.** Любая команда по SSH меняет поведение (де-оффлоад, побудка туннеля).
   Замер обязан идти с клиента, при полном молчании на роутере.

## Метрики, которые смотрим

- мутационный счёт — **выживших должно быть 0**;
- покрытие `rt-proxy` — сейчас ~32% строк, но важны не проценты, а то, что каждый полевой
  отказ имеет тест, который краснеет от его возврата;
- число сьютов и шагов приёмки — растёт вместе с каждым новым классом отказа;
- расхождение репозиторий/роутер — обязано быть нулевым перед любым «проверено».

## Чего не покрывает ничто

- **MIPS.** Ни один прогон не выполнялся на MT7621. Код архитектурно-независим, но это
  рассуждение, а не измерение.
- **Перезагрузка роутера** и многочасовая стабильность туннеля.
- **Чужой провайдер.** Блокировки различаются по регионам; пул прокси у одного пользователя
  живой, у другого вырезан целиком.

Эти три пункта закрываются только полем. Их надо называть вслух в описании релиза, а не
выдавать за проверенное.
